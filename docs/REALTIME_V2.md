# 实时同步与战术地图 v2

实时观测的硬期限为 **2 秒**，时间基准由 `/api/time` 的最小 RTT 校准确定。逾期、失败、重复和乱序样本直接丢弃；网络恢复只发送当前最新值。没有新增原始观测或事件归档、补传和复盘。陆战与空战使用独立地图坐标，不建立坐标拟合。

静态底图和地图元数据不按位置期限删除。当前局的人工标绘保存在 `WT_LIVE_DIR/room-*.json`。既有录制文件和离线分析工具保留；加载含多个历史局的旧房间文件时，先保存一份 `room-*.legacy.json`，再将运行文件限制为当前局。

## 采集与融合

- 本机身份为随机 128 位 `device_id`，保存在 Windows `%LOCALAPPDATA%/wt-tactical-command/device-id`。通过临时文件和硬链接原子发布，避免同时启动生成不同身份。会话 ID 每次启动重新生成。
- 每个端点只有一个最新值槽位；观测最多 3 个并发请求，静态图片有独立保留通道（最多 6 张等待资源）。观测不会重试，图片允许有界重试。
- 每条样本包含采样起始时间、单调时间、序号、代次和 `map_context`。采样过程中上下文变化则丢弃；地图图片完成后才允许该地图进入融合。
- 服务端解压和批次解析在阻塞任务中进行，解压上限 16 MiB、每批最多 128 条。网络处理不持有房间更新锁。
- 每房间只有一个状态任务。待处理样本按来源和端点合并（最多 2048 槽、8 MiB），100 ms 更新与广播，命令队列最多 128 条。持久化使用独立串行磁盘任务，写入临时文件后原子替换。
- 身份由设备关联自身观测；匿名单位只在同地图图片、范围、网格、阵营和类别下匹配。跨来源采样相差最多 250 ms，距离门限陆战 8 米、空战 50 米。关联有歧义时保留不同单位。
- 同设备新会话替代旧会话；换载具、重生、陆空视图切换和短暂断网不换局。全部成员明确退出持续 20 秒才结束当前局。设置提供“开始新一局”。

## 上传协议

`POST /api/ingest` 使用 Bearer 上传口令，可 gzip：

```json
{
  "device_id": "随机持久化设备身份",
  "session": "每次进程启动的独立身份",
  "nickname": "用户设置的呼号",
  "player": "可选玩家标识",
  "version": "2.0.0",
  "clock": {"synced": true, "offset_ms": 0, "rtt_ms": 15},
  "records": [{"session": "同上", "ep": "/map_obj.json", "seq": 42,
    "wall_ms": 1700000000000, "mono_ns": 1000000, "ts_server_ms": 1700000000000,
    "epoch": 1, "map_context": "采样时的地图上下文", "body": "[]"}]
}
```

响应报告 `accepted`、`dup`、`out_of_order`、`dropped.too_old/from_future/no_sync/overflow`。
图片通过 `POST /api/image?session=...&hash=...` 单独上传，服务端校验 SHA256。

## WebSocket 与协作

`/api/live?room=...&key=...&nick=...` 使用独立房间口令。`hello` 与 `state` 含 `protocol:2`、`state_seq` 和 `draw_revision`。`hello` 包含完整当前状态和标绘，`state` 包含陆空各自的 `map_age`，成员含 `age_ms`。

```json
{"op":"put","protocol":2,"battle":"当前局 ID","op_id":"操作 UUID","base_version":0,
 "d":{"id":"标绘 UUID","kind":"point","scope":"ground","map_context":"当前地图上下文","pts":[[100,100]],"label":"集合"}}
```

客户端使用 `op:"put"` / `op:"del"`；`put` 载荷字段为 `d`，删除为 `id`。每个请求携带 `op_id` 和 `base_version`。服务端返回 `type:"draw"` 确认及版本；同一操作重送只返回原确认。基于旧版本的编辑返回 `version_conflict` 和完整当前快照，不能覆盖队友的新修改。标绘最多 600 个，标绘与删除版本总计最多 4096 个，操作去重缓存最多 512 个。

状态序号断档、广播遗漏、重连或确认超过 3 秒未知时，请求 `{"op":"sync"}` 获取快照。断线期间禁用共享编辑，不盲目重发结果未知操作；旧连接的事件回调通过连接代次隔离。旧网页缺少操作身份和版本时服务端拒绝修改，需刷新升级。

## 绘制与资源

地图使用 Canvas 2D 的底图/网格、单位、标绘、交互预览四层。地图尺寸由可用空间决定，实际图片等比例显示；绘制和命中共用投影。双图独立平移和缩放，共用工具栏操作当前地图。单位平滑只向最新有效位置收敛；过期单位立即移除。标绘按对象引用与相关层状态变化重绘，类别图标 LRU 缓存最多 128 个。

网页和 Windows 共享 `shared/ui-theme.json`。直角深灰面板、橄榄色选中态、地图为主画面；移动端安全区、44 px 触控控件和收起详情抽屉。密度和敌情策略位于个人设置。

采用游戏内置战术地图的符号系统，不再使用 Wiki 载具剪影。2026-10-11 从用户正在运行的游戏只读 HTTP 接口获取 `icons.ttf` 和地图页面：攻击机为扁菱形、战斗机为菱形、轰炸机为倒三角、轻坦为双竖线、中坦为小圆点、履带/坦歼为横线、防空车为倒三角加横线。10 个原生字形对应 12 个已核验类别映射；字体路径编入 `src/data/mapGlyphs.json`，不等待网络图片或字体加载。SVG 预览、输入文件 SHA256 和映射在 `public/icons/map/sources.json`；提取工具为 `tools/extract_map_icons.py`。保持字形比例及游戏原生相对大小，另加阵营色和深色细描边。

该字体中的 `H`（重坦/直升机）为空，舰艇没有已核验的类别映射；这些类别显示中性符号与收到的类别文字，不编造原生图形或用剪影替代。没有明确型号来源时不猜测型号。

本人使用金色 `#fac81e` 方向箭头。本人来源按房间保存并绑定稳定设备身份；自动识别后记住设备，短暂离线、队友加入或重启不会换人。设置中的“金色本人标记”允许明确选择自己的采集端或仅观看。队友回传保持绿色，其他友军保持蓝色。

底图更新比较包含图片地址、鉴权参数、地图上下文、代次和完整范围；Canvas 底图层的重绘键包含图片地址、就绪尺寸和可用状态。开始新一局后重置视图和交互状态，后续底图自动加载；临时图片失败自动重试。服务端手动开始新一局保留已就绪的静态地图，清空标绘和实时单位；等待新采样时显示断流，新的地图上下文正常替换。

视觉参考：[Bohemia CT_MAP_MAIN](https://community.bistudio.com/wiki/CT_MAP_MAIN)。地图符号来源：游戏内置 `http://127.0.0.1:8111/` 与 `icons.ttf`（实际端口需自动探测）。

## 发布与回退

先服务器，再 Windows 采集端发行包，最后网页。备份现有二进制、静态站目录、环境文件和房间状态；不清理历史数据。保持上传口令和房间口令分别配置。部署后的 `WT_MAX_SKEW_MS` 为 2000，关闭缺少时钟同步的旧客户端接收。

发行包使用 `deploy/package.sh SERVER_URL EXE_PATH`，可通过 `WT_PACKAGE_TOKEN_FILE` 读取内部上传口令，模板始终保持占位符。每次生成发行包输出 SHA256。不要将口令传入命令行、终端输出或 Git。
